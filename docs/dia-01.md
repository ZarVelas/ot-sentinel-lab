
# OT-SENTINEL: Industrial Control System Security Lab

A hands-on OT/ICS security research environment built on commodity hardware, 
replicating a Purdue Model network topology to demonstrate real-world attack 
vectors against industrial protocols and validate detection capabilities.

---

## Overview

OT-SENTINEL simulates a Level 1–3 Purdue Model architecture using four virtual 
machines across two physical hosts. The lab generates authentic Modbus TCP 
traffic from a live process running on OpenPLC Runtime, executes unauthenticated 
write attacks against the PLC, and detects them through passive network monitoring 
with Zeek.

No synthetic datasets. No prefabricated captures. Every packet was generated by 
a running process under active attack.

---

## Lab Architecture

| VM | Role | Purdue Level | Host | Hypervisor |
|---|---|---|---|---|
| ot-sentinel-plc | OpenPLC Runtime (virtual PLC) | Level 1 | PC1 Windows 11 | VMware |
| ot-sentinel-engineering-station | Engineering workstation | Level 2 | PC2 Ubuntu 24.04 | VirtualBox |
| ot-sentinel-kali-attacker | Adversarial node | Level 3 | PC1 Windows 11 | VMware |
| ot-sentinel-security-onion | Passive IDS/NSM sensor | Monitor | PC2 Ubuntu 24.04 | VirtualBox |

---

## Attack Scenario

**Vector:** Unauthenticated Modbus TCP write (Function Code 0x05 — Write Single Coil)  
**Target:** Level 1 PLC running a simulated pump process  
**Effect:** Forced coil state change — pump activated outside normal process conditions  
**Detection:** Zeek with ICS protocol parsers, generating structured Modbus logs

## Normative Framework

Attack scenarios are mapped against:

- **ISA/IEC 62443-3-3** — System security requirements (SR 1.1, SR 5.1)
- **NCA OTCC-1:2022** — Saudi Arabia's OT cybersecurity controls (OT-5.1, OT-7.1, OT-10.1)
